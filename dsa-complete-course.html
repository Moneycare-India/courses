Module 1
What & Why of DSA

What is DSA?

Data Structures are ways of organizing data in memory (arrays, lists, trees, graphs). Algorithms are step-by-step procedures to solve problems on that data. Together: DSA.

The point isn't memorizing trivia. It's developing the ability to:

  1. Look at a problem and recognize its shape.
  2. Pick the right structure to model the data.
  3. Pick the right algorithm to operate on it.
  4. Reason about how it scales — will it be fast enough on real input?

Why does it matter for production code?

You're already using DSA every day, even if you don't think about it:

  • Dictionary<K,V> — hash table. O(1) average lookup.
  • List<T>.Sort() — variant of introsort. O(n log n).
  • EF Core's IQueryable — internally builds an expression tree.
  • JSON parsers — recursive descent over a string.
  • Routing — a trie maps URL paths to handlers.
  • Caching — LRU = doubly-linked list + hash map.
  • EF Core change tracker — graph traversal.
  • Pagination — depends on whether you sort or use seek.

The brute force vs optimized story

For almost every problem, there's a brute force solution that's "obvious" but slow, and a smart solution that's faster. The interview gauntlet trains you to recognize when O(n²) won't survive 100k inputs and how to drop it to O(n log n) or O(n).

Example: "Given an array, do any two numbers sum to target?"

Brute force — O(n²)

bool TwoSum(int[] nums, int target)
{
    for (int i = 0; i < nums.Length; i++)
        for (int j = i + 1; j < nums.Length; j++)
            if (nums[i] + nums[j] == target)
                return true;
    return false;
}

n=10⁵ → 10¹⁰ ops → seconds. n=10⁶ → minutes.

Hash set — O(n)

bool TwoSum(int[] nums, int target)
{
    var seen = new HashSet<int>();
    foreach (var x in nums)
    {
        if (seen.Contains(target - x)) return true;
        seen.Add(x);
    }
    return false;
}

n=10⁶ → done in milliseconds.

That gap — from "minutes" to "milliseconds" — is the whole point of DSA. You stop fearing scale because you can predict whether your code will survive it.

Module 2
Time Complexity & Big-O

What is time complexity?

A measure of how the running time grows as input size grows. We don't care about microseconds on your laptop — we care about the shape of the curve.

Big-O notation

O(f(n)) = "the running time grows no faster than a constant times f(n) as n → ∞."

Three rules:

  1. Drop constants: O(2n) = O(n).
  2. Drop lower-order terms: O(n² + n) = O(n²).
  3. Worst case is what we usually quote (unless explicitly amortized or average).

Best / average / worst case

Different inputs of the same size can take different time. Quicksort:

  • Best: O(n log n) — perfect pivots.
  • Average: O(n log n).
  • Worst: O(n²) — already-sorted input with bad pivot.

When someone asks "what's the time complexity?" — they usually mean worst case. Always state which one you're discussing.

Amortized analysis

Some operations are usually fast but occasionally slow. List<T>.Add is O(1) most of the time, but O(n) when the internal array doubles. Amortized O(1) means the average cost over many operations is O(1) even though individual ones might be slower.

Module 3
Space Complexity

Same idea as time, but for memory. Counts extra memory beyond the input.

How to count it

  • Each variable: O(1).
  • Array of length n: O(n).
  • 2D array n×m: O(nm).
  • Hash map of n entries: O(n).
  • Recursion: O(depth) for the call stack.

Examples

// O(1) extra space — only a few scalars
int Sum(int[] a)
{
    int s = 0;
    for (int i = 0; i < a.Length; i++) s += a[i];
    return s;
}

// O(n) extra — the new array
int[] Doubled(int[] a)
{
    var r = new int[a.Length];
    for (int i = 0; i < a.Length; i++) r[i] = a[i] * 2;
    return r;
}

// O(n) — recursion depth
int FactRec(int n) => n == 0 ? 1 : n * FactRec(n - 1);

// O(log n) — recursion depth in binary search tree of height log n
int BstHeight(Node? root) => root == null ? 0
    : 1 + Math.Max(BstHeight(root.Left), BstHeight(root.Right));

In-place vs out-of-place

An in-place algorithm uses O(1) or O(log n) extra space (modifies input). An out-of-place algorithm creates a new structure.

AlgorithmIn-place?Extra space
Bubble / Insertion sortYesO(1)
Quick sortYes (with stack)O(log n)
Merge sortNoO(n)
Heap sortYesO(1)
Counting sortNoO(n + k)

Time-space trade-offs

Most optimizations spend space to save time. The hash-set TwoSum from Module 1 is O(n) time + O(n) space, vs O(n²) time + O(1) space for the brute force. Memoization in DP is the canonical example — you cache results to avoid recomputing.

Module 4
Recursion

The mental model

A recursive function calls itself with a smaller version of the problem. Two parts:

  1. Base case — when to stop.
  2. Recursive case — how to reduce the problem.
int Factorial(int n)
{
    if (n <= 1) return 1;          // base case
    return n * Factorial(n - 1);   // recursive case
}

Trace it on paper once

Factorial(4)
= 4 * Factorial(3)
= 4 * 3 * Factorial(2)
= 4 * 3 * 2 * Factorial(1)
= 4 * 3 * 2 * 1
= 24

The call stack

Each call pushes a frame. Each return pops one. If you go too deep → StackOverflowException. .NET's default thread stack is 1 MB — typically 10k–50k frames before it blows up. For deep recursion, convert to iteration.

Tail recursion

If the recursive call is the LAST thing the function does, some compilers can transform it into a loop (no stack growth). C# does NOT reliably tail-call optimize. F# does. JIT may or may not.

Classic recursive problems

Fibonacci — be careful, brute is O(2ⁿ)

Brute — O(2ⁿ)

int Fib(int n) => n < 2
    ? n
    : Fib(n - 1) + Fib(n - 2);
// Fib(40) takes seconds.
// Fib(60) takes hours.

Memoized — O(n)

Dictionary<int,long> memo = new();
long Fib(int n)
{
    if (n < 2) return n;
    if (memo.TryGetValue(n, out var v)) return v;
    return memo[n] = Fib(n - 1) + Fib(n - 2);
}
// Fib(60) instant.

Iterative is even better — O(n) time, O(1) space

long Fib(int n)
{
    if (n < 2) return n;
    long a = 0, b = 1;
    for (int i = 2; i <= n; i++) (a, b) = (b, a + b);
    return b;
}

Recurrence relations

Recursive functions can be analyzed by writing a recurrence:

  • Factorial: T(n) = T(n-1) + 1 → O(n)
  • Fibonacci (brute): T(n) = T(n-1) + T(n-2) + 1 → O(φⁿ) ≈ O(2ⁿ)
  • Binary search: T(n) = T(n/2) + 1 → O(log n)
  • Merge sort: T(n) = 2T(n/2) + n → O(n log n)
  • Subsets/permutations: T(n) = nT(n-1) → O(n!)

Master theorem (quick version)

For T(n) = aT(n/b) + O(n^d):

  • If a < b^d → T(n) = O(n^d) — the work outside dominates
  • If a = b^d → T(n) = O(n^d log n) — balanced
  • If a > b^d → T(n) = O(n^(log_b a)) — the recursion dominates

Examples: Merge sort: 2T(n/2) + n → a=2, b=2, d=1 → balanced → O(n log n). Binary search: T(n/2) + 1 → a=1, b=2, d=0 → balanced → O(log n).

Module 5
Math Foundations

Modular arithmetic

When numbers get huge, problems often ask "answer modulo 10⁹ + 7". Why? Keeps results in int/long range. Crypto and competitive programming use this constantly.

const long MOD = 1_000_000_007L;
long Add(long a, long b) => (a + b) % MOD;
long Mul(long a, long b) => (a * b) % MOD;

// Modular exponentiation — a^b mod m in O(log b)
long PowMod(long a, long b, long m)
{
    long result = 1;
    a %= m;
    while (b > 0)
    {
        if ((b & 1) == 1) result = result * a % m;
        a = a * a % m;
        b >>= 1;
    }
    return result;
}

GCD & LCM

// Euclidean algorithm — O(log min(a,b))
long Gcd(long a, long b) => b == 0 ? a : Gcd(b, a % b);
long Lcm(long a, long b) => a / Gcd(a, b) * b;

Primes — Sieve of Eratosthenes

// All primes up to n in O(n log log n)
bool[] Sieve(int n)
{
    var isPrime = new bool[n + 1];
    Array.Fill(isPrime, true);
    isPrime[0] = isPrime[1] = false;
    for (int i = 2; (long)i * i <= n; i++)
        if (isPrime[i])
            for (int j = i * i; j <= n; j += i)
                isPrime[j] = false;
    return isPrime;
}

The basic operators

Common tricks

// Test if bit i is set
bool IsSet(int n, int i) => (n & (1 << i)) != 0;

// Set / clear / toggle bit i
int Set(int n, int i)    => n |  (1 << i);
int Clear(int n, int i)  => n & ~(1 << i);
int Toggle(int n, int i) => n ^  (1 << i);

// Count set bits — O(popcount)
int PopCount(uint n)
{
    int c = 0;
    while (n > 0) { n &= (n - 1); c++; }   // clears lowest set bit
    return c;
}
// Or: BitOperations.PopCount(n);   // .NET built-in, fastest

// Is power of two?
bool IsPow2(int n) => n > 0 && (n & (n - 1)) == 0;

// Lowest set bit
int LowestBit(int n) => n & -n;

// Swap two ints without temp
void Swap(ref int a, ref int b) { a ^= b; b ^= a; a ^= b; }

XOR magic — the find-the-unique problem

Problem: every element appears twice except one. Find it.

int FindUnique(int[] a)
{
    int x = 0;
    foreach (var v in a) x ^= v;     // pairs cancel out
    return x;
}
// O(n) time, O(1) space — beats hash set's O(n) space

Bitmask DP

For small n (≤ 20), you can represent a subset as an int. Iterate over all 2ⁿ subsets:

for (int mask = 0; mask < (1 << n); mask++)
    for (int i = 0; i < n; i++)
        if ((mask & (1 << i)) != 0) { /* element i is in subset */ }

Used in Travelling Salesman, set-cover DPs, etc. (Module 35.)

Module 8
Arrays

What is an array?

A contiguous block of memory holding a fixed number of equally-sized elements. Indexing is O(1) because the address is just base + index × elementSize.

int[] a = { 5, 8, 2, 9, 1 };

  index:   0    1    2    3    4
  memory: [5]  [8]  [2]  [9]  [1]    ← contiguous, all the same size

List<T> — the dynamic array

Internally a T[] with a length and capacity. When full, allocates a new array twice as big and copies. That's why Add is amortized O(1).

Classic problem: max subarray sum (Kadane's algorithm)

Problem

Given an array of integers (positive and negative), find the contiguous subarray with the largest sum.
Example: [-2, 1, -3, 4, -1, 2, 1, -5, 4] → max sum is 6 (subarray [4, -1, 2, 1]).

Brute force — O(n²)

int MaxSubarray(int[] a)
{
    int best = int.MinValue;
    for (int i = 0; i < a.Length; i++)
    {
        int sum = 0;
        for (int j = i; j < a.Length; j++)
        {
            sum += a[j];
            best = Math.Max(best, sum);
        }
    }
    return best;
}

Try every starting index, then every ending index. n=10⁵ → 10¹⁰ ops, too slow.

Kadane — O(n)

int MaxSubarray(int[] a)
{
    int best = a[0], cur = a[0];
    for (int i = 1; i < a.Length; i++)
    {
        cur = Math.Max(a[i], cur + a[i]);
        // either start fresh at a[i],
        // or extend the previous subarray
        best = Math.Max(best, cur);
    }
    return best;
}

Insight: if the running sum becomes negative, drop it — starting fresh is better.

Other classic array problems

  • Move zeros to end (two pointers).
  • Rotate array by k.
  • Find missing number from 1..n (XOR or sum trick).
  • Stock buy/sell — single pass tracking min so far.
  • Trapping rain water (two pointers / monotonic stack).

Strings

A string is an array of characters. In .NET, string is immutable — every "modification" creates a new string. Use StringBuilder or char[] for in-place work.

Common string operations

string s = "hello";

// O(n) on length
int len = s.Length;
char c = s[2];                           // O(1)
bool eq = s == "hello";                   // O(n) value compare

string upper = s.ToUpper();               // O(n) NEW string
string concat = s + " world";             // O(n+m) NEW string
string sub = s.Substring(1, 3);           // O(n)

// For many concatenations:
var sb = new StringBuilder();
foreach (var w in words) sb.Append(w);    // amortized O(1) per Append
string result = sb.ToString();            // O(total length)

Classic problem: anagram check

Problem

Are two strings anagrams of each other? (Same characters, different order.)
Example: "listen" and "silent" → true.

Sort both — O(n log n)

bool IsAnagram(string a, string b)
{
    if (a.Length != b.Length) return false;
    var arrA = a.ToCharArray();
    var arrB = b.ToCharArray();
    Array.Sort(arrA);
    Array.Sort(arrB);
    return arrA.SequenceEqual(arrB);
}

Frequency count — O(n)

bool IsAnagram(string a, string b)
{
    if (a.Length != b.Length) return false;
    var count = new int[26];        // assuming a-z
    for (int i = 0; i < a.Length; i++)
    {
        count[a[i] - 'a']++;
        count[b[i] - 'a']--;
    }
    return count.All(c => c == 0);
}

Classic problem: longest substring without repeating chars

Problem

"abcabcbb" → 3 ("abc"). "bbbbb" → 1.

Brute — O(n³)

int LongestUnique(string s)
{
    int best = 0;
    for (int i = 0; i < s.Length; i++)
        for (int j = i; j < s.Length; j++)
            if (s.Substring(i, j - i + 1)
                 .Distinct().Count() == j - i + 1)
                best = Math.Max(best, j - i + 1);
    return best;
}

Sliding window — O(n)

int LongestUnique(string s)
{
    var seen = new Dictionary<char,int>();
    int left = 0, best = 0;
    for (int right = 0; right < s.Length; right++)
    {
        if (seen.TryGetValue(s[right], out int idx) && idx >= left)
            left = idx + 1;
        seen[s[right]] = right;
        best = Math.Max(best, right - left + 1);
    }
    return best;
}

Window grows; whenever we see a repeat, jump left past it. (See Module 40 — Sliding Window pattern.)

String comparison gotchas

  • == on strings does value comparison in C# (because of operator overload). In Java/JS, prefer .equals() / ===.
  • Locale-aware comparison: StringComparison.OrdinalIgnoreCase is fastest for case-insensitive ASCII.
  • Use string.Intern sparingly — locks strings in memory forever.

Module 10
Linked Lists

What & why

A sequence of nodes, each pointing to the next. Insertion/deletion at a known position is O(1) — no shifting. The cost: random access is O(n), and each node has a pointer overhead.

Singly linked list:
  [data|next]→[data|next]→[data|next]→null

Doubly linked list:
  null←[prev|data|next]⇄[prev|data|next]⇄[prev|data|next]→null

Singly linked list in C#

public class ListNode
{
    public int Val;
    public ListNode? Next;
    public ListNode(int val, ListNode? next = null) { Val = val; Next = next; }
}

Reverse a linked list — the canonical interview question

Recursive — O(n) time, O(n) stack

ListNode? Reverse(ListNode? head)
{
    if (head?.Next == null) return head;
    ListNode? newHead = Reverse(head.Next);
    head.Next.Next = head;
    head.Next = null;
    return newHead;
}

Iterative — O(n) time, O(1) space

ListNode? Reverse(ListNode? head)
{
    ListNode? prev = null;
    ListNode? cur = head;
    while (cur != null)
    {
        var next = cur.Next;
        cur.Next = prev;
        prev = cur;
        cur = next;
    }
    return prev;
}

Detect a cycle — Floyd's tortoise & hare

Problem

Does the list contain a cycle? (Some node's next points back to an earlier node.)

Hash set — O(n) time, O(n) space

bool HasCycle(ListNode? head)
{
    var seen = new HashSet<ListNode>();
    while (head != null)
    {
        if (!seen.Add(head)) return true;
        head = head.Next;
    }
    return false;
}

Floyd's algorithm — O(n) time, O(1) space

bool HasCycle(ListNode? head)
{
    var slow = head;
    var fast = head;
    while (fast != null && fast.Next != null)
    {
        slow = slow!.Next;
        fast = fast.Next.Next;
        if (slow == fast) return true;
    }
    return false;
}

Two pointers move at different speeds. If there's a cycle, they meet. (See Module 41.)

Other classic linked list problems

  • Find middle node (slow + fast pointer).
  • Merge two sorted lists.
  • Remove Nth node from end (two-pointer with N gap).
  • Detect cycle and find its start.
  • Check palindrome (reverse second half).

When to use a linked list

Honestly, rarely in production C# code. List<T> wins for cache-friendliness in almost every case. Use linked lists when:

  • You frequently insert/delete from the middle at a known node.
  • You need O(1) splicing of two lists.
  • You're implementing LRU cache (doubly-linked list + hash map).

Module 11
Stacks

LIFO — Last In, First Out. Push/Pop at one end, both O(1).

Push 1, 2, 3:
  [3]   ← top
  [2]
  [1]

Pop → 3, then 2, then 1.

C# usage

var stack = new Stack<int>();
stack.Push(1);
stack.Push(2);
int top = stack.Peek();      // 2 (look without removing)
int p = stack.Pop();         // 2 (remove)
int count = stack.Count;

Where stacks appear

  • Function call stack (recursion).
  • Undo/redo (two stacks).
  • Parsing / matching brackets / expression evaluation.
  • DFS (iterative version uses an explicit stack).
  • Browser back button.
  • Monotonic stack — find next greater/smaller element.

Classic problem: valid parentheses

Problem

"()[]{}" → true. "([)]" → false.

bool IsValid(string s)
{
    var stack = new Stack<char>();
    var pairs = new Dictionary<char,char>
    {
        [')'] = '(', [']'] = '[', ['}'] = '{'
    };

    foreach (var c in s)
    {
        if (c == '(' || c == '[' || c == '{')
            stack.Push(c);
        else
        {
            if (stack.Count == 0 || stack.Pop() != pairs[c])
                return false;
        }
    }
    return stack.Count == 0;
}
// O(n) time, O(n) space

Monotonic stack — next greater element

Problem

For each element, find the next greater element to its right. [2, 1, 2, 4, 3] → [4, 2, 4, -1, -1].

int[] NextGreater(int[] a)
{
    var result = new int[a.Length];
    Array.Fill(result, -1);
    var stack = new Stack<int>();   // stores indices

    for (int i = 0; i < a.Length; i++)
    {
        while (stack.Count > 0 && a[stack.Peek()] < a[i])
            result[stack.Pop()] = a[i];
        stack.Push(i);
    }
    return result;
}
// O(n) — each index pushed and popped at most once

This trick — push, then pop while the new element invalidates old ones — solves a class of problems: largest rectangle in histogram, daily temperatures, stock span.

Deque — double-ended queue

Insert/remove from either end in O(1). .NET doesn't have a built-in deque, but LinkedList<T> works (you use AddFirst/AddLast/RemoveFirst/RemoveLast). For competitive scenarios, a circular array implementation is faster.

Sliding window maximum — classic deque problem

Problem

Given an array and window size k, return the max in each window. [1,3,-1,-3,5,3,6,7] k=3 → [3,3,5,5,6,7].

Brute — O(n·k)

int[] MaxWindow(int[] a, int k)
{
    var r = new int[a.Length - k + 1];
    for (int i = 0; i + k <= a.Length; i++)
    {
        int max = a[i];
        for (int j = 1; j < k; j++)
            max = Math.Max(max, a[i + j]);
        r[i] = max;
    }
    return r;
}

Monotonic deque — O(n)

int[] MaxWindow(int[] a, int k)
{
    var dq = new LinkedList<int>();   // indices, decreasing values
    var r = new int[a.Length - k + 1];

    for (int i = 0; i < a.Length; i++)
    {
        // remove out-of-window from front
        if (dq.Count > 0 && dq.First!.Value == i - k)
            dq.RemoveFirst();
        // remove smaller-or-equal from back
        while (dq.Count > 0 && a[dq.Last!.Value] <= a[i])
            dq.RemoveLast();
        dq.AddLast(i);
        if (i >= k - 1) r[i - k + 1] = a[dq.First!.Value];
    }
    return r;
}

Priority Queue — heap-backed

Returns the smallest (or largest) element in O(log n). Backed by a binary heap.

// .NET 6+
var pq = new PriorityQueue<string, int>();   // element, priority (lower = sooner)
pq.Enqueue("b", 2);
pq.Enqueue("a", 1);
pq.Enqueue("c", 3);
string next = pq.Dequeue();    // "a"

// Max heap — invert priority
var maxPq = new PriorityQueue<string, int>();
maxPq.Enqueue("low", -1);
maxPq.Enqueue("high", -10);
maxPq.Dequeue();   // "high" — most negative = highest priority

Used everywhere: Dijkstra (shortest path), top-K problems, K-way merge, scheduling, A* search. We cover the heap data structure deeply in Module 17.

Module 13
Hash Tables

The single most useful data structure

A hash table maps keys to values with O(1) average insert / lookup / delete. The trick: a hash function turns the key into an array index.

Hash("alice") = 47 → bucket 47 holds (alice, 30)
Hash("bob")   = 12 → bucket 12 holds (bob, 25)
Hash("carol") = 47 → COLLISION → chained in bucket 47

How collisions are handled

  • Chaining (most common, .NET): each bucket is a linked list of entries.
  • Open addressing: probe to the next empty slot (linear/quadratic/double hashing).

Why O(1) "average"?

If the hash function distributes keys uniformly and the load factor (entries / buckets) stays bounded, each bucket has O(1) entries on average. Worst case (everything collides) is O(n) — but that requires an adversarial hash function. .NET handles this with randomized hash codes.

C# Dictionary essentials

users[1] = "Alice";
users[2] = "Bob";

if (users.ContainsKey(3)) { ... }
users.Remove(2);
foreach (var (k, v) in users) { ... }

HashSet — like Dictionary but values-only

    // first time we've seen x

Custom hash codes — when keys are your types

public record Point(int X, int Y);
// Records get value equality + hash for free.

// For classes:
public class Point : IEquatable<Point>
{
    public int X { get; }
    public int Y { get; }

Two Sum — the classic hash table problem (revisited)

int[] TwoSum(int[] nums, int target)
{
    var seen = new Dictionary<int,int>();   // value → index
    for (int i = 0; i < nums.Length; i++)
    {
        int need = target - nums[i];
        if (seen.TryGetValue(need, out int j))
            return new[] { j, i };
        seen[nums[i]] = i;
    }
    return Array.Empty<int>();
}
// O(n) time, O(n) space

Other hash-table-shaped problems

  • Group anagrams (key = sorted string or char-count signature).
  • Subarray sum equals K (running sum + count map).
  • First non-repeating character.
  • Longest consecutive sequence.
  • Detect duplicates within distance k.

Pitfalls

  • Mutable keys whose hash code can change → entries become "lost".
  • Iterating in undefined order. SortedDictionary if you need order.
  • Memory overhead — typically 2–3× the data size.
  • Cache-unfriendly compared to arrays for small N.

Module 14
Binary Trees

What is a tree?

A connected acyclic graph. One special node is the root. Each node has zero or more children and exactly one parent (except the root).

A binary tree = each node has at most 2 children (Left, Right).

             1            ← root, depth 0
           /   \
          2     3         ← depth 1
         / \     \
        4   5     6       ← depth 2
                 / \
                7   8     ← depth 3 (leaves are 4, 5, 7, 8)
                          height = 3 (longest root-to-leaf)

Common terminology

  • Root — top node, no parent.
  • Leaf — no children.
  • Depth of node — distance from root (root is 0).
  • Height of tree — max depth.
  • Subtree — a node + all its descendants.
  • Balanced — heights of left and right subtrees differ by at most 1, recursively.
  • Complete — every level full except possibly the last, which fills left-to-right.
  • Perfect — every internal node has 2 children, all leaves at same depth.

Node definition in C#

  • Tries (Module 19): autocomplete, IP routing.
  • Expression trees: parsers, EF Core's IQueryable.
  • Decision trees: ML, rule engines.
  • Game trees: chess engines (minimax).

void Preorder(TreeNode? n)
{

}

{
    if (n == null) return;

}

{
    if (n == null) return;

    Postorder(n.Right);
    Visit(n);                  // root last
}

Iterative inorder with a stack

List<int> Inorder(TreeNode? root)
{
    var result = new List<int>();
    var stack = new Stack<TreeNode>();
    var cur = root;
    while (cur != null || stack.Count > 0)
    {
        while (cur != null)
        {
            stack.Push(cur);
            cur = cur.Left;
        }
        cur = stack.Pop();
        result.Add(cur.Val);
        cur = cur.Right;
    }
    return result;
}

Level-order — BFS with a queue

List<List<int>> LevelOrder(TreeNode? root)
{
    var result = new List<List<int>>();
    if (root == null) return result;

    var queue = new Queue<TreeNode>();
    queue.Enqueue(root);

    while (queue.Count > 0)
    {
        int size = queue.Count;
        var level = new List<int>();
        for (int i = 0; i < size; i++)
        {
            var n = queue.Dequeue();
            level.Add(n.Val);
            if (n.Left != null) queue.Enqueue(n.Left);
            if (n.Right != null) queue.Enqueue(n.Right);
        }
        result.Add(level);
    }
    return result;
}

Classic problem: max depth of binary tree

int MaxDepth(TreeNode? n) => n == null
    ? 0
    : 1 + Math.Max(MaxDepth(n.Left), MaxDepth(n.Right));
// O(n) time, O(h) recursion depth — h = log n if balanced, n if not

Lowest common ancestor (LCA)

TreeNode? Lca(TreeNode? root, TreeNode p, TreeNode q)
{
    if (root == null || root == p || root == q) return root;
    var L = Lca(root.Left, p, q);
    var R = Lca(root.Right, p, q);
    if (L != null && R != null) return root;   // p and q split here
    return L ?? R;
}

Module 16
Binary Search Trees (BST)

The BST property

For every node: all values in the left subtree are less, all values in the right subtree are greater. (And recursively the same applies to subtrees.)

           8
         /   \
        3     10
       / \      \
      1   6      14
         / \    /
        4   7  13

Inorder traversal of a BST gives sorted output. That's the magic.

Operations on a balanced BST — all O(log n)

// Search
TreeNode? Search(TreeNode? n, int target)
{
    if (n == null || n.Val == target) return n;
    return target < n.Val ? Search(n.Left, target) : Search(n.Right, target);
}

// Insert
TreeNode Insert(TreeNode? n, int val)
{
    if (n == null) return new TreeNode(val);
    if (val < n.Val) n.Left = Insert(n.Left, val);
    else if (val > n.Val) n.Right = Insert(n.Right, val);
    return n;
}

// Delete — three cases (no child / one child / two children)
TreeNode? Delete(TreeNode? n, int val)
{
    if (n == null) return null;
    if (val < n.Val) n.Left = Delete(n.Left, val);
    else if (val > n.Val) n.Right = Delete(n.Right, val);
    else
    {
        if (n.Left == null) return n.Right;
        if (n.Right == null) return n.Left;
        // Two children: replace with inorder successor
        var succ = MinNode(n.Right);
        n.Val = succ.Val;
        n.Right = Delete(n.Right, succ.Val);
    }
    return n;
}

TreeNode MinNode(TreeNode n)
{
    while (n.Left != null) n = n.Left;
    return n;
}

The catch — unbalanced BSTs degrade to O(n)

Insert 1, 2, 3, 4, 5 in order → you get a right-leaning chain that's just a linked list. Hence self-balancing trees (Module 18). .NET's SortedDictionary is a red-black tree.

Validate a BST — common bug

Wrong — only checks immediate children

bool IsBst(TreeNode? n)
{
    if (n == null) return true;
    if (n.Left != null && n.Left.Val >= n.Val) return false;
    if (n.Right != null && n.Right.Val <= n.Val) return false;
    return IsBst(n.Left) && IsBst(n.Right);
}
// Misses: 10 → left=5 → right=15 (15 is in left subtree of 10!)

Correct — pass min/max bounds

bool IsBst(TreeNode? n, long min = long.MinValue, long max = long.MaxValue)
{
    if (n == null) return true;
    if (n.Val <= min || n.Val >= max) return false;
    return IsBst(n.Left, min, n.Val) && IsBst(n.Right, n.Val, max);
}

Heaps & Priority Queue

What is a heap?

A complete binary tree with the heap property: every parent is ≤ (min-heap) or ≥ (max-heap) its children. The min/max is always at the root → O(1) peek.

Min-heap:
              1
            /   \
           3     5
          / \   /
         8   9 7

Min is always at root.

The trick: store as an array

// Index 0 = root
// For node at index i:
//   parent      = (i - 1) / 2
//   left child  = 2*i + 1
//   right child = 2*i + 2

int[] heap = { 1, 3, 5, 8, 9, 7 };
//             ^root

Operations

OperationTimeWhat it does
Peek (min/max)O(1)Return root
Insert (push)O(log n)Add at end, "sift up"
Extract (pop)O(log n)Swap root with last, "sift down"
Build from arrayO(n)"Heapify" all internal nodes

Where heaps are essential

  • Dijkstra's shortest path — fetch closest unvisited.
  • A* search.
  • Top-K problems — keep a heap of size K.
  • Median in a stream — two heaps.
  • K-way merge — merge K sorted lists.
  • Heap sort.
  • OS scheduling.

Top-K largest elements

Sort then take K — O(n log n)

int[] TopK(int[] a, int k)
{
    var sorted = a.OrderByDescending(x => x).ToArray();
    return sorted.Take(k).ToArray();
}

Min-heap of size K — O(n log k)

int[] TopK(int[] a, int k)
{
    var heap = new PriorityQueue<int,int>();   // min-heap
    foreach (var x in a)
    {
        heap.Enqueue(x, x);
        if (heap.Count > k) heap.Dequeue();    // drop smallest
    }
    var result = new int[k];
    for (int i = k - 1; i >= 0; i--) result[i] = heap.Dequeue();
    return result;
}
// For n=10⁹, k=10: massive speedup

Median in a data stream

Maintain two heaps: a max-heap for the lower half, a min-heap for the upper half. Median is at the top of one (or average of both tops if balanced). Insert is O(log n), median lookup is O(1).

Module 18
Self-Balancing Trees

Plain BSTs degrade to O(n). Self-balancing trees re-shape after inserts/deletes to keep height ≈ log n.

AVL trees

  • For every node, |height(left) − height(right)| ≤ 1.
  • Restored via rotations after insert/delete.
  • Strictly balanced → fastest reads.
  • More expensive writes than red-black trees.

Red-black trees

  • Each node colored red or black; rules ensure no path is > 2× longer than any other.
  • Looser balance → faster writes than AVL.
  • The standard library workhorse — used by Java's TreeMap, C++'s std::map, .NET's SortedDictionary.

B-trees and B+ trees

Multi-way trees with each node holding many keys (typically dozens to hundreds). Used by databases (SQL Server clustered indexes, PostgreSQL, MySQL InnoDB) and filesystems. Why? Disks read in pages — fitting many keys per node minimizes disk reads.

TreeInsertSearchWhere used
AVLO(log n)O(log n)Read-heavy in-memory
Red-blackO(log n)O(log n)SortedDictionary, std::map
B-treeO(log n)O(log n)Databases, filesystems
Splay treeO(log n) amortizedO(log n) amortizedCaching: recently accessed → near root

For interviews, knowing they exist and the trade-off (loose vs tight balance, in-memory vs disk) is usually enough. Implementing a red-black tree from scratch is rarely asked.

           root
           /  \
          c    d
          |    |
          a    o
         / \   |
        t*  r  g*
            |
           *or d*

Implementation in C#

public class Trie
{
    private class Node
    {
        public Dictionary<char, Node> Children = new();
        public bool IsEnd;
    }

    private readonly Node _root = new();

    public void Insert(string word)
    {
        var n = _root;
        foreach (var c in word)
        {
            if (!n.Children.TryGetValue(c, out var next))
                n.Children[c] = next = new Node();
            n = next;
        }
        n.IsEnd = true;
    }

    public bool Search(string word) => FindNode(word) is { IsEnd: true };

    public bool StartsWith(string prefix) => FindNode(prefix) != null;

    private Node? FindNode(string s)
    {
        var n = _root;
        foreach (var c in s)
        {
            if (!n.Children.TryGetValue(c, out var next)) return null;
            n = next;
        }
        return n;
    }
}

Where tries shine

  • Autocomplete — every keystroke triggers a prefix lookup.
  • Spell check — combined with edit distance.
  • IP routing tables — longest prefix match.
  • URL routing — many web frameworks store routes in tries.
  • T9 keyboards.
  • Word games (Boggle, Scrabble solvers).

Memory cost

A trie with ASCII can use 26+ pointers per node. For large dictionaries, switch from Dictionary<char, Node> to a 26-element array, or use a compressed trie / radix tree where chains of single-child nodes are collapsed.

Module 21
BFS & DFS

Two ways to visit every reachable node. Both O(V + E).

BFS — Breadth-First Search

Visit all vertices at distance 1 first, then 2, then 3. Uses a queue.

void Bfs(List<List<int>> graph, int start)
{
    var visited = new bool[graph.Count];
    var queue = new Queue<int>();

    queue.Enqueue(start);
    visited[start] = true;

    while (queue.Count > 0)
    {
        int v = queue.Dequeue();
        Visit(v);
        foreach (var u in graph[v])
        {
            if (!visited[u])
            {
                visited[u] = true;
                queue.Enqueue(u);
            }
        }
    }
}

Use BFS when you need shortest path (in unweighted graphs) — the first time you reach a node is via the shortest path.

Shortest path with BFS

int[] ShortestPaths(List<List<int>> graph, int start)
{
    var dist = new int[graph.Count];
    Array.Fill(dist, -1);
    var queue = new Queue<int>();
    queue.Enqueue(start);
    dist[start] = 0;
    while (queue.Count > 0)
    {
        int v = queue.Dequeue();
        foreach (var u in graph[v])
            if (dist[u] == -1)
            {
                dist[u] = dist[v] + 1;
                queue.Enqueue(u);
            }
    }
    return dist;
}

DFS — Depth-First Search

Go as deep as possible, then backtrack. Uses recursion (or explicit stack).

void Dfs(List<List<int>> graph, int start)
{
    var visited = new bool[graph.Count];
    DfsHelper(graph, start, visited);
}

void DfsHelper(List<List<int>> graph, int v, bool[] visited)
{
    visited[v] = true;
    Visit(v);
    foreach (var u in graph[v])
        if (!visited[u]) DfsHelper(graph, u, visited);
}

Use DFS for: connectivity, cycle detection, topological sort, finding all paths, tree problems.

Number of islands — classic BFS/DFS on grid

Problem

Given a 2D grid of '1' (land) and '0' (water), count the islands. Islands connect horizontally and vertically.

int NumIslands(char[][] grid)
{
    if (grid.Length == 0) return 0;
    int rows = grid.Length, cols = grid[0].Length;
    int count = 0;

    void Dfs(int r, int c)
    {
        if (r < 0 || c < 0 || r >= rows || c >= cols || grid[r][c] != '1')
            return;
        grid[r][c] = '0';      // mark visited
        Dfs(r + 1, c); Dfs(r - 1, c);
        Dfs(r, c + 1); Dfs(r, c - 1);
    }

    for (int r = 0; r < rows; r++)
        for (int c = 0; c < cols; c++)
            if (grid[r][c] == '1') { count++; Dfs(r, c); }
    return count;
}
// O(R·C) time and space

Dijkstra's algorithm

// graph[u] = list of (neighbor, weight) tuples; weights ≥ 0
int[] Dijkstra(List<List<(int to, int w)>> graph, int start)
{
    var dist = new int[graph.Count];
    Array.Fill(dist, int.MaxValue);
    dist[start] = 0;

    var heap = new PriorityQueue<int, int>();
    heap.Enqueue(start, 0);

    while (heap.Count > 0)
    {
        heap.TryDequeue(out int v, out int d);
        if (d > dist[v]) continue;        // stale entry — skip

        foreach (var (u, w) in graph[v])
        {
            int nd = d + w;
            if (nd < dist[u])
            {
                dist[u] = nd;
                heap.Enqueue(u, nd);
            }
        }
    }
    return dist;
}

Bellman-Ford

Handles negative edges. Slower but more general. Detects negative cycles (if a distance can still be improved after V-1 iterations, there's a negative cycle).

int[] BellmanFord(int V, List<(int from, int to, int w)> edges, int start)
{
    var dist = new int[V];
    Array.Fill(dist, int.MaxValue);
    dist[start] = 0;

    for (int i = 0; i < V - 1; i++)
        foreach (var (u, v, w) in edges)
            if (dist[u] != int.MaxValue && dist[u] + w < dist[v])
                dist[v] = dist[u] + w;

    // Detect negative cycle
    foreach (var (u, v, w) in edges)
        if (dist[u] != int.MaxValue && dist[u] + w < dist[v])
            throw new Exception("Negative cycle");

    return dist;
}

Floyd-Warshall — all-pairs shortest paths

int[,] FloydWarshall(int[,] g)   // g[i,j] = direct distance, or INF
{
    int n = g.GetLength(0);
    var d = (int[,])g.Clone();
    for (int k = 0; k < n; k++)
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                if (d[i, k] + d[k, j] < d[i, j])
                    d[i, j] = d[i, k] + d[k, j];
    return d;
}
// Three nested loops; works for V up to ~500

Module 23
Minimum Spanning Tree

Given a connected weighted undirected graph, find the subset of edges that connects all vertices with minimum total weight. The result is a tree (V-1 edges).

Two classic algorithms

Kruskal — sort edges + Union-Find

// Sort all edges by weight; greedily add edges that don't form a cycle.
int Kruskal(int V, List<(int u, int v, int w)> edges)
{
    edges.Sort((a, b) => a.w.CompareTo(b.w));
    var dsu = new DSU(V);
    int total = 0, used = 0;
    foreach (var (u, v, w) in edges)
    {
        if (dsu.Union(u, v))           // returns true if they weren't connected
        {
            total += w;
            if (++used == V - 1) break;
        }
    }
    return total;
}
// O(E log E) — dominated by sort
// (DSU shown in Module 37)

Prim — grow from a starting vertex with a heap

int Prim(List<List<(int to, int w)>> graph)
{
    var inMst = new bool[graph.Count];
    var heap = new PriorityQueue<(int v, int w), int>();
    heap.Enqueue((0, 0), 0);
    int total = 0;
    while (heap.Count > 0)
    {
        heap.TryDequeue(out var cur, out var w);
        if (inMst[cur.v]) continue;
        inMst[cur.v] = true;
        total += w;
        foreach (var (to, ew) in graph[cur.v])
            if (!inMst[to]) heap.Enqueue((to, ew), ew);
    }
    return total;
}
// O((V + E) log V)

When MST appears in real life

  • Network design — laying cable to connect cities cheaply.
  • Clustering — single-linkage hierarchical clustering.
  • Approximate solutions to TSP.

Topological Sort & SCC

Topological sort

For a DAG (directed acyclic graph), produce an ordering where every edge u→v has u before v. Used for: course prerequisites, build dependencies (make/MSBuild), task scheduling.

Kahn's algorithm — BFS based

List<int> TopoSort(List<List<int>> graph)
{
    int V = graph.Count;
    var indeg = new int[V];
    for (int u = 0; u < V; u++)
        foreach (var v in graph[u]) indeg[v]++;

    var q = new Queue<int>();
    for (int i = 0; i < V; i++) if (indeg[i] == 0) q.Enqueue(i);

    var result = new List<int>();
    while (q.Count > 0)
    {
        int v = q.Dequeue();
        result.Add(v);
        foreach (var u in graph[v])
            if (--indeg[u] == 0) q.Enqueue(u);
    }
    if (result.Count != V) throw new Exception("Has cycle");
    return result;
}
// O(V + E)

Strongly connected components

In a directed graph, an SCC is a maximal set of vertices that can all reach each other. Used for: deadlock detection, optimizer dependency analysis, web link analysis.

Two algorithms:

  • Kosaraju — two DFS passes (forward then transposed graph). O(V + E).
  • Tarjan — single DFS using a stack and low-link values. O(V + E). Slightly faster constants.

Implementations are 30–50 lines each — recognize the use case, look up the canonical implementation when needed.

Cycle detection

  • Undirected: DFS — if you visit a node already in the current path (and it's not the parent), there's a cycle.
  • Directed: DFS with three colors — white (unseen), gray (in current path), black (done). Hitting a gray node = cycle.
bool HasCycleDirected(List<List<int>> graph)
{
    int V = graph.Count;
    var color = new int[V];   // 0=white, 1=gray, 2=black

    bool Dfs(int v)
    {
        color[v] = 1;
        foreach (var u in graph[v])
        {
            if (color[u] == 1) return true;
            if (color[u] == 0 && Dfs(u)) return true;
        }
        color[v] = 2;
        return false;
    }

    for (int i = 0; i < V; i++)
        if (color[i] == 0 && Dfs(i)) return true;
    return false;
}

Module 25
Binary Search & Variants

The basic algorithm

On a sorted array, we can find a target in O(log n) by repeatedly halving the search space.

int BinarySearch(int[] a, int target)
{
    int lo = 0, hi = a.Length - 1;
    while (lo <= hi)
    {
        int mid = lo + (hi - lo) / 2;     // avoids overflow
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

20 iterations enough for an array of a million. 30 for a billion. Always consider whether your data can be sorted to enable binary search.

Off-by-one is the killer

Three loop invariants:

  • while (lo <= hi) — search closed interval [lo, hi]; updates: mid+1 / mid-1.
  • while (lo < hi) — search half-open [lo, hi); updates: mid+1 / mid.
  • while (lo + 1 < hi) — leaves [lo, hi] with two candidates at end; pick after the loop.

Pick one and stick with it. Mixing causes infinite loops or off-by-ones. Recommended: closed interval as above.

Lower bound / upper bound

Find the first index where a[i] >= target (lower bound) or a[i] > target (upper bound). The number of equal elements is upper - lower.

// First index where a[i] >= target
int LowerBound(int[] a, int target)
{
    int lo = 0, hi = a.Length;
    while (lo < hi)
    {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}

Binary search the answer

This is the killer pattern: when the input is NOT sorted but the answer has a monotonic feasibility predicate (something feasible at value k is also feasible at k+1, but not at k-1), binary search the answer space.

Problem: Koko eating bananas

Piles of bananas. Koko can eat at speed k bananas/hour (one pile per hour, even if < k). Min k to finish in H hours?

int MinEatingSpeed(int[] piles, int H)
{
    int lo = 1, hi = piles.Max();
    while (lo < hi)
    {
        int mid = lo + (hi - lo) / 2;
        long hoursNeeded = piles.Sum(p => (long)((p + mid - 1) / mid));
        if (hoursNeeded <= H) hi = mid;       // feasible — try slower
        else lo = mid + 1;                     // infeasible — eat faster
    }
    return lo;
}
// O(N log M) where M = max pile

Other "binary search the answer" problems: split array largest sum, capacity to ship within D days, min days to make bouquets, find min in rotated sorted array.

Module 26
Basic Sorting

You'll never write these in production (use Array.Sort) but you must understand them — the patterns appear everywhere.

Bubble sort — O(n²)

void BubbleSort(int[] a)
{
    int n = a.Length;
    for (int i = 0; i < n - 1; i++)
    {
        bool swapped = false;
        for (int j = 0; j < n - i - 1; j++)
            if (a[j] > a[j + 1])
            {
                (a[j], a[j + 1]) = (a[j + 1], a[j]);
                swapped = true;
            }
        if (!swapped) break;        // already sorted
    }
}

Selection sort — O(n²)

void SelectionSort(int[] a)
{
    for (int i = 0; i < a.Length - 1; i++)
    {
        int minIdx = i;
        for (int j = i + 1; j < a.Length; j++)
            if (a[j] < a[minIdx]) minIdx = j;
        if (minIdx != i) (a[i], a[minIdx]) = (a[minIdx], a[i]);
    }
}

Insertion sort — O(n²) worst, O(n) best

Best when the array is nearly sorted. Used as the base case in introsort/timsort for small subarrays.

void InsertionSort(int[] a)
{
    for (int i = 1; i < a.Length; i++)
    {
        int cur = a[i], j = i - 1;
        while (j >= 0 && a[j] > cur)
        {
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = cur;
    }
}

Stability

A stable sort preserves the relative order of equal-keyed elements. Matters when sorting by multiple criteria sequentially.

Module 27
Efficient Sorting

Merge sort — O(n log n), stable, O(n) space

Divide the array in half, sort each half recursively, merge. The merge step is the heart.

void MergeSort(int[] a, int lo, int hi)
{
    if (lo >= hi) return;
    int mid = lo + (hi - lo) / 2;
    MergeSort(a, lo, mid);
    MergeSort(a, mid + 1, hi);
    Merge(a, lo, mid, hi);
}

void Merge(int[] a, int lo, int mid, int hi)
{
    var tmp = new int[hi - lo + 1];
    int i = lo, j = mid + 1, k = 0;
    while (i <= mid && j <= hi)
        tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++];
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= hi)  tmp[k++] = a[j++];
    Array.Copy(tmp, 0, a, lo, tmp.Length);
}

Always O(n log n) — predictable. Used to sort linked lists (no random access needed) and external sorts (data on disk).

Quick sort — O(n log n) avg, O(n²) worst, O(log n) extra space

Pick a pivot, partition (smaller left, larger right), recurse on each side.

void QuickSort(int[] a, int lo, int hi)
{
    if (lo >= hi) return;
    int p = Partition(a, lo, hi);
    QuickSort(a, lo, p - 1);
    QuickSort(a, p + 1, hi);
}

int Partition(int[] a, int lo, int hi)
{
    int pivot = a[hi];          // last element as pivot
    int i = lo - 1;
    for (int j = lo; j < hi; j++)
        if (a[j] < pivot)
            (a[++i], a[j]) = (a[j], a[i]);
    (a[i + 1], a[hi]) = (a[hi], a[i + 1]);
    return i + 1;
}

Faster constants than merge sort in practice. Worst case is O(n²) when pivots are bad — mitigate with random or median-of-three pivot. Real-world implementations (introsort) detect bad recursion and switch to heap sort.

Heap sort — O(n log n), O(1) extra space

Build a max-heap, then repeatedly extract the max to the end. In-place.

void HeapSort(int[] a)
{
    int n = a.Length;
    // Build heap (heapify all internal nodes)
    for (int i = n / 2 - 1; i >= 0; i--) SiftDown(a, i, n);
    // Extract max repeatedly
    for (int i = n - 1; i > 0; i--)
    {
        (a[0], a[i]) = (a[i], a[0]);
        SiftDown(a, 0, i);
    }
}

void SiftDown(int[] a, int i, int n)
{
    while (true)
    {
        int l = 2 * i + 1, r = 2 * i + 2, largest = i;
        if (l < n && a[l] > a[largest]) largest = l;
        if (r < n && a[r] > a[largest]) largest = r;
        if (largest == i) break;
        (a[i], a[largest]) = (a[largest], a[i]);
        i = largest;
    }
}

Built-in choice in .NET

Array.Sort / List<T>.Sort use introsort: quicksort that switches to heap sort if recursion goes too deep, plus insertion sort for small subarrays. Best of both worlds.

Module 28
Non-Comparison Sorting

Comparison sorts have a lower bound of Ω(n log n). To go faster, you need to know more about the data.

Counting sort — O(n + k)

For integers in a small range [0, k]. Count occurrences, then write out.

void CountingSort(int[] a, int k)
{
    var count = new int[k + 1];
    foreach (var x in a) count[x]++;
    int idx = 0;
    for (int v = 0; v <= k; v++)
        while (count[v]-- > 0) a[idx++] = v;
}
// O(n + k); great when k is bounded (e.g., counting ages 0..120)

Radix sort — O(d·(n + b))

Sort by digits, least significant first. d = number of digits, b = base. For 32-bit ints with base 256, that's 4 passes.

Bucket sort — O(n) average

Spread elements into k buckets, sort each, concatenate. Works well when input is uniformly distributed.

When you'd actually use these

  • Counting sort: counting votes by age, sorting score bins, anagram comparison.
  • Radix sort: sorting fixed-length strings or integers in massive datasets.
  • Bucket sort: histogram-style data with known distribution.

For 99% of real C# code, just use Array.Sort.

Two Pointers, Sliding Window, Prefix Sum

Three indispensable techniques for array problems. Master these and a quarter of LeetCode falls.

Two pointers

Use two indices that move based on conditions. Often turns O(n²) into O(n).

Problem: pair sum in sorted array

Sorted array. Two indices that sum to target?

bool HasPairSum(int[] a, int target)
{
    int lo = 0, hi = a.Length - 1;
    while (lo < hi)
    {
        int s = a[lo] + a[hi];
        if (s == target) return true;
        if (s < target) lo++;        // need bigger
        else hi--;                    // need smaller
    }
    return false;
}
// O(n)

More two-pointer problems: container with most water, 3Sum, valid palindrome, remove duplicates from sorted array, move zeros.

Sliding window

Maintain a contiguous window [left, right] and slide it across, updating an aggregate (sum, count, set of elements) in O(1) per step.

Problem: longest substring with at most K distinct chars

"eceba", k=2 → 3 ("ece").

int LongestKDistinct(string s, int k)
{
    var count = new Dictionary<char,int>();
    int left = 0, best = 0;
    for (int right = 0; right < s.Length; right++)
    {
        count[s[right]] = count.GetValueOrDefault(s[right]) + 1;
        while (count.Count > k)
        {
            count[s[left]]--;
            if (count[s[left]] == 0) count.Remove(s[left]);
            left++;
        }
        best = Math.Max(best, right - left + 1);
    }
    return best;
}
// O(n) — left and right each advance at most n times

Prefix sum

Precompute cumulative sums so any range sum is O(1).

// prefix[i] = sum of a[0..i-1]
int[] BuildPrefix(int[] a)
{
    var p = new int[a.Length + 1];
    for (int i = 0; i < a.Length; i++) p[i + 1] = p[i] + a[i];
    return p;
}

// Sum of a[l..r] inclusive
int RangeSum(int[] prefix, int l, int r) => prefix[r + 1] - prefix[l];

Subarray sum equals K — prefix sum + hash map

Problem

Count subarrays whose sum equals k. [1,1,1], k=2 → 2.

Brute — O(n²)

int Count(int[] a, int k)
{
    int total = 0;
    for (int i = 0; i < a.Length; i++)
    {
        int s = 0;
        for (int j = i; j < a.Length; j++)
        {
            s += a[j];
            if (s == k) total++;
        }
    }
    return total;
}

Prefix + map — O(n)

int Count(int[] a, int k)
{
    var seen = new Dictionary<int,int> { [0] = 1 };
    int sum = 0, total = 0;
    foreach (var x in a)
    {
        sum += x;
        // Subarrays ending here with sum k
        // are previous prefixes with sum (sum - k)
        total += seen.GetValueOrDefault(sum - k);
        seen[sum] = seen.GetValueOrDefault(sum) + 1;
    }
    return total;
}

2D prefix sums work the same way (image/grid range queries in O(1) after O(R·C) preprocessing).

Module 30
Brute Force

The simplest possible solution: try every possibility. Often O(2ⁿ) or O(n!) — but it's the right starting point because:

  • It establishes correctness.
  • You can compare optimized solutions against it on small inputs.
  • Sometimes it's actually fast enough for the input size.

The right way to brute-force

  1. Enumerate all candidates.
  2. Check each.
  3. Return the answer (or all answers).

Common brute force shapes

ShapeComplexityExample
All pairsO(n²)Closest pair, two-sum
All triplesO(n³)3-sum, max product of 3
All subsetsO(2ⁿ)Subset sum, power set
All permutationsO(n!)TSP, anagram generation
All grid pathsO(2^(R+C))Naïve unique paths

How to optimize away from brute

  • Sort first — opens up two-pointer or binary search.
  • Hash table — turn O(n²) lookups into O(n).
  • Memoize — for recursive brute force with overlapping subproblems → DP.
  • Prune — backtracking with cuts.
  • Greedy — if local optimal leads to global optimal.
  • Math — closed-form formula instead of enumerating.

Module 31
Greedy

At each step, take the locally optimal choice. If you can prove greedy gives the global optimum, you're done — usually O(n) or O(n log n).

The hard part: proving greedy works

Greedy doesn't always work. The key question: "does the locally best choice never sabotage the future?" Two common proof techniques:

  • Exchange argument — show any non-greedy step can be swapped for a greedy one without making the answer worse.
  • Stays-ahead argument — show after k steps the greedy solution is at least as good as any other.

Classic greedy: activity selection

Problem

Given activities with (start, end) times, schedule the maximum number that don't overlap.

int MaxActivities((int s, int e)[] acts)
{
    Array.Sort(acts, (a, b) => a.e.CompareTo(b.e));   // by end time
    int count = 0, lastEnd = int.MinValue;
    foreach (var (s, e) in acts)
        if (s >= lastEnd) { count++; lastEnd = e; }
    return count;
}
// O(n log n) — sort dominates
// Greedy choice: always pick the activity that ends earliest among compatible ones.

Other greedy classics

  • Coin change — works greedily for canonical coin systems (US coins) but NOT for arbitrary (e.g., {1, 3, 4} for amount 6 — greedy gives 3 coins, optimal is 2).
  • Huffman coding — compress text by giving frequent chars short codes. Greedy via priority queue.
  • Kruskal & Prim — MST (Module 23).
  • Dijkstra — shortest path (Module 22).
  • Job scheduling with deadlines — sort by profit, schedule latest possible slot.
  • Gas station problem.
  • Jump game — track furthest reachable.

When greedy fails — fall back to DP

If a problem's optimal solution requires combining choices in non-obvious ways (e.g., 0/1 knapsack), greedy fails — need dynamic programming.

Module 32
Divide & Conquer

Three steps:

  1. Divide the problem into smaller subproblems of the same shape.
  2. Conquer them recursively.
  3. Combine their answers.

Examples: merge sort, quick sort, binary search, Strassen's matrix multiplication, FFT.

Recurrence and Master Theorem

Already covered in Module 4. Quick reminder:

  • Merge sort: 2 subproblems of size n/2 + O(n) combine → O(n log n).
  • Binary search: 1 subproblem of size n/2 + O(1) → O(log n).
  • Karatsuba multiplication: 3 subproblems of size n/2 + O(n) → O(n^log₂3) ≈ O(n^1.58).

Maximum subarray with D&C — O(n log n)

(Less efficient than Kadane but a great D&C example.)

int Solve(int[] a, int lo, int hi)
{
    if (lo == hi) return a[lo];
    int mid = (lo + hi) / 2;
    int leftMax = Solve(a, lo, mid);
    int rightMax = Solve(a, mid + 1, hi);
    int crossMax = MaxCrossing(a, lo, mid, hi);
    return Math.Max(Math.Max(leftMax, rightMax), crossMax);
}

int MaxCrossing(int[] a, int lo, int mid, int hi)
{
    int leftSum = int.MinValue, sum = 0;
    for (int i = mid; i >= lo; i--)
    {
        sum += a[i];
        if (sum > leftSum) leftSum = sum;
    }
    int rightSum = int.MinValue; sum = 0;
    for (int i = mid + 1; i <= hi; i++)
    {
        sum += a[i];
        if (sum > rightSum) rightSum = sum;
    }
    return leftSum + rightSum;
}

Module 33
Dynamic Programming Foundations

DP is the technique for problems where:

  1. Overlapping subproblems — the same smaller problem comes up many times.
  2. Optimal substructure — the optimal answer is built from optimal answers to smaller subproblems.

The trick: compute each subproblem once, save the answer, reuse it.

Two implementation styles

1. Top-down (memoization)

Recursion + cache. Easier to write; same code as brute force plus a memo table.

Dictionary<int, long> memo = new();

long Fib(int n)
{
    if (n < 2) return n;
    if (memo.TryGetValue(n, out var v)) return v;
    return memo[n] = Fib(n - 1) + Fib(n - 2);
}

2. Bottom-up (tabulation)

Iterative, fill in subproblems in order. Usually faster (no recursion overhead) and avoids stack overflow.

long Fib(int n)
{
    if (n < 2) return n;
    var dp = new long[n + 1];
    dp[0] = 0; dp[1] = 1;
    for (int i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
    return dp[n];
}

Often: optimize space

If dp[i] only depends on the last few entries, store just those.

long Fib(int n)
{
    if (n < 2) return n;
    long a = 0, b = 1;
    for (int i = 2; i <= n; i++) (a, b) = (b, a + b);
    return b;
}
// O(n) time, O(1) space

The DP recipe

  1. Define the state — what does dp[i] (or dp[i][j]) represent?
  2. Find the recurrence — how do you compute dp[i] from smaller states?
  3. Identify base cases — what are the trivial answers?
  4. Decide order — which states to fill first.
  5. Optionally optimize space.

How to recognize a DP problem

  • "How many ways…", "minimum cost…", "longest…", "is it possible to…"
  • Brute force is recursive and re-explores the same states.
  • Each step has a small set of choices.

Classic 1D DPs

Climbing stairs

Problem

You climb stairs taking 1 or 2 steps. How many distinct ways to reach step n?

// dp[i] = ways to reach step i
// dp[i] = dp[i-1] + dp[i-2] — Fibonacci!
int ClimbStairs(int n)
{
    if (n <= 2) return n;
    int a = 1, b = 2;
    for (int i = 3; i <= n; i++) (a, b) = (b, a + b);
    return b;
}

House robber

Problem

Rob houses on a street; can't rob two adjacent. Max money?

int Rob(int[] money)
{
    int prev2 = 0, prev1 = 0;
    foreach (var m in money)
    {
        int cur = Math.Max(prev1, prev2 + m);
        // either skip this house (prev1) or rob it (prev2 + m)
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}
// O(n) time, O(1) space

Coin change — minimum coins

Problem

Given coin denominations and an amount, return min number of coins. -1 if impossible.

int CoinChange(int[] coins, int amount)
{
    var dp = new int[amount + 1];
    Array.Fill(dp, amount + 1);   // sentinel for "impossible"
    dp[0] = 0;
    for (int a = 1; a <= amount; a++)
        foreach (var c in coins)
            if (c <= a) dp[a] = Math.Min(dp[a], dp[a - c] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
}
// O(amount × coins.Length)

Longest increasing subsequence (LIS)

// O(n²) DP
int LisN2(int[] a)
{
    int n = a.Length;
    var dp = new int[n];
    Array.Fill(dp, 1);
    for (int i = 1; i < n; i++)
        for (int j = 0; j < i; j++)
            if (a[j] < a[i]) dp[i] = Math.Max(dp[i], dp[j] + 1);
    return dp.Max();
}

// O(n log n) — patience sorting / binary search
int LisNLogN(int[] a)
{
    var tails = new List<int>();
    foreach (var x in a)
    {
        int idx = tails.BinarySearch(x);
        if (idx < 0) idx = ~idx;
        if (idx == tails.Count) tails.Add(x);
        else tails[idx] = x;
    }
    return tails.Count;
}

All follow the same template: dp[i] describes some property up to index i, recurrence considers the last "step" backwards.

Classic 2D DPs

0/1 Knapsack

Problem

N items, each with weight w[i] and value v[i]. Capacity W. Pick a subset (each at most once) to maximize value.

// dp[i][c] = max value with first i items, capacity c
int Knapsack(int[] w, int[] v, int W)
{
    int n = w.Length;
    var dp = new int[n + 1, W + 1];
    for (int i = 1; i <= n; i++)
        for (int c = 0; c <= W; c++)
        {
            dp[i, c] = dp[i - 1, c];                        // skip item
            if (w[i - 1] <= c)
                dp[i, c] = Math.Max(dp[i, c],
                                     dp[i - 1, c - w[i - 1]] + v[i - 1]);
        }
    return dp[n, W];
}
// O(nW) time and space; can reduce to O(W) space with rolling array

Longest Common Subsequence (LCS)

int Lcs(string a, string b)
{
    int n = a.Length, m = b.Length;
    var dp = new int[n + 1, m + 1];
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            dp[i, j] = a[i - 1] == b[j - 1]
                ? dp[i - 1, j - 1] + 1
                : Math.Max(dp[i - 1, j], dp[i, j - 1]);
    return dp[n, m];
}
// O(nm)

Edit distance (Levenshtein)

Problem

Min number of insert/delete/replace operations to transform string a into b.

int EditDistance(string a, string b)
{
    int n = a.Length, m = b.Length;
    var dp = new int[n + 1, m + 1];
    for (int i = 0; i <= n; i++) dp[i, 0] = i;
    for (int j = 0; j <= m; j++) dp[0, j] = j;
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            dp[i, j] = a[i - 1] == b[j - 1]
                ? dp[i - 1, j - 1]
                : 1 + Math.Min(dp[i - 1, j - 1],          // replace
                       Math.Min(dp[i - 1, j],              // delete
                                dp[i, j - 1]));            // insert
    return dp[n, m];
}
// O(nm) — used in spell checkers, diff tools, DNA alignment

Unique paths in a grid

int UniquePaths(int rows, int cols)
{
    var dp = new int[rows, cols];
    for (int r = 0; r < rows; r++) dp[r, 0] = 1;
    for (int c = 0; c < cols; c++) dp[0, c] = 1;
    for (int r = 1; r < rows; r++)
        for (int c = 1; c < cols; c++)
            dp[r, c] = dp[r - 1, c] + dp[r, c - 1];
    return dp[rows - 1, cols - 1];
}

Module 36
Backtracking

Backtracking is brute-force-with-pruning. Build a candidate solution incrementally; whenever a partial solution can't possibly succeed, "back up" and try a different choice.

The shape

void Backtrack(state)
{
    if (IsSolution(state)) { Record(state); return; }
    foreach (choice in Candidates(state))
    {
        if (!IsValid(state, choice)) continue;     // pruning
        Apply(state, choice);
        Backtrack(state);
        Undo(state, choice);                        // backtrack
    }
}

Permutations

List<List<int>> Permute(int[] nums)
{
    var result = new List<List<int>>();
    var path = new List<int>();
    var used = new bool[nums.Length];

    void Backtrack()
    {
        if (path.Count == nums.Length)
        {
            result.Add(new List<int>(path));
            return;
        }
        for (int i = 0; i < nums.Length; i++)
        {
            if (used[i]) continue;
            used[i] = true;
            path.Add(nums[i]);
            Backtrack();
            path.RemoveAt(path.Count - 1);
            used[i] = false;
        }
    }

    Backtrack();
    return result;
}
// O(n · n!)

Subsets

List<List<int>> Subsets(int[] nums)
{
    var result = new List<List<int>>();
    var path = new List<int>();

    void Backtrack(int start)
    {
        result.Add(new List<int>(path));
        for (int i = start; i < nums.Length; i++)
        {
            path.Add(nums[i]);
            Backtrack(i + 1);
            path.RemoveAt(path.Count - 1);
        }
    }

    Backtrack(0);
    return result;
}
// O(n · 2ⁿ)

N-Queens

List<List<string>> SolveNQueens(int n)
{
    var result = new List<List<string>>();
    var cols = new bool[n];
    var diag1 = new bool[2 * n];   // r + c
    var diag2 = new bool[2 * n];   // r - c + n
    var queens = new int[n];

    void Backtrack(int row)
    {
        if (row == n)
        {
            var board = new List<string>();
            for (int r = 0; r < n; r++)
                board.Add(new string('.', queens[r]) + "Q" +
                          new string('.', n - queens[r] - 1));
            result.Add(board);
            return;
        }
        for (int c = 0; c < n; c++)
        {
            if (cols[c] || diag1[row + c] || diag2[row - c + n]) continue;
            cols[c] = diag1[row + c] = diag2[row - c + n] = true;
            queens[row] = c;
            Backtrack(row + 1);
            cols[c] = diag1[row + c] = diag2[row - c + n] = false;
        }
    }

    Backtrack(0);
    return result;
}

DSU, Segment Tree, Fenwick Tree

Disjoint Set Union (Union-Find)

Tracks a partition of n elements into disjoint sets. Two operations:

  • Find(x) — which set is x in?
  • Union(x, y) — merge their sets.

With both path compression and union by rank, both ops are nearly O(1) amortized (technically O(α(n)), the inverse Ackermann function — practically constant).

public class DSU
{
    private readonly int[] _parent;
    private readonly int[] _rank;

    public DSU(int n)
    {
        _parent = new int[n];
        _rank = new int[n];
        for (int i = 0; i < n; i++) _parent[i] = i;
    }

    public int Find(int x)
    {
        if (_parent[x] != x) _parent[x] = Find(_parent[x]);   // path compression
        return _parent[x];
    }

    public bool Union(int x, int y)
    {
        int rx = Find(x), ry = Find(y);
        if (rx == ry) return false;
        if (_rank[rx] < _rank[ry]) (rx, ry) = (ry, rx);
        _parent[ry] = rx;
        if (_rank[rx] == _rank[ry]) _rank[rx]++;
        return true;
    }
}

Where DSU shines: Kruskal MST, dynamic connectivity ("are u and v in the same component?"), counting components, account merging, image segmentation.

Segment Tree

Supports range queries (sum, min, max, ...) and point updates in O(log n). Built on an array of size up to 4n.

// Sum segment tree
public class SegTree
{
    private readonly int[] _t;
    private readonly int _n;

    public SegTree(int[] a)
    {
        _n = a.Length;
        _t = new int[4 * _n];
        Build(a, 1, 0, _n - 1);
    }

    void Build(int[] a, int node, int lo, int hi)
    {
        if (lo == hi) { _t[node] = a[lo]; return; }
        int mid = (lo + hi) / 2;
        Build(a, 2 * node, lo, mid);
        Build(a, 2 * node + 1, mid + 1, hi);
        _t[node] = _t[2 * node] + _t[2 * node + 1];
    }

    public int RangeSum(int l, int r) => Query(1, 0, _n - 1, l, r);

    int Query(int node, int lo, int hi, int l, int r)
    {
        if (r < lo || l > hi) return 0;
        if (l <= lo && hi <= r) return _t[node];
        int mid = (lo + hi) / 2;
        return Query(2 * node, lo, mid, l, r) +
               Query(2 * node + 1, mid + 1, hi, l, r);
    }

    public void Update(int idx, int val) => Up(1, 0, _n - 1, idx, val);

    void Up(int node, int lo, int hi, int idx, int val)
    {
        if (lo == hi) { _t[node] = val; return; }
        int mid = (lo + hi) / 2;
        if (idx <= mid) Up(2 * node, lo, mid, idx, val);
        else Up(2 * node + 1, mid + 1, hi, idx, val);
        _t[node] = _t[2 * node] + _t[2 * node + 1];
    }
}

Fenwick Tree (Binary Indexed Tree, BIT)

Simpler than segment trees — supports prefix sums and point updates in O(log n). Less general (no arbitrary range query out of the box) but very compact.

public class Fenwick
{
    private readonly int[] _t;
    public Fenwick(int n) { _t = new int[n + 1]; }
    public void Update(int i, int delta)
    {
        for (i++; i < _t.Length; i += i & -i) _t[i] += delta;
    }
    public int Prefix(int i)
    {
        int s = 0;
        for (i++; i > 0; i -= i & -i) s += _t[i];
        return s;
    }
    public int Range(int l, int r) => Prefix(r) - Prefix(l - 1);
}

Use for: count of inversions, cumulative frequency, range-sum-with-updates, online order statistics.

Pattern: Two Pointers

When to use

  • Sorted array / linked list and you're searching for pairs/triplets.
  • Reverse / palindrome check.
  • Partition problems (move zeros, sort colors).
  • Merge two sorted arrays.

Template

int left = 0, right = n - 1;
while (left < right)
{
    if (Condition(left, right)) return ...;
    if (NeedBigger(left, right)) left++;
    else right--;
}

3Sum — find all triplets summing to 0

List<List<int>> ThreeSum(int[] nums)
{
    Array.Sort(nums);
    var result = new List<List<int>>();
    for (int i = 0; i < nums.Length - 2; i++)
    {
        if (i > 0 && nums[i] == nums[i - 1]) continue;     // skip dups
        int l = i + 1, r = nums.Length - 1;
        while (l < r)
        {
            int sum = nums[i] + nums[l] + nums[r];
            if (sum == 0)
            {
                result.Add(new List<int> { nums[i], nums[l], nums[r] });
                while (l < r && nums[l] == nums[l + 1]) l++;
                while (l < r && nums[r] == nums[r - 1]) r--;
                l++; r--;
            }
            else if (sum < 0) l++;
            else r--;
        }
    }
    return result;
}
// O(n²) — sorting is O(n log n), outer × two-pointer is O(n²)

Container with most water

int MaxArea(int[] h)
{
    int l = 0, r = h.Length - 1, best = 0;
    while (l < r)
    {
        int area = (r - l) * Math.Min(h[l], h[r]);
        best = Math.Max(best, area);
        if (h[l] < h[r]) l++;        // shorter side limits us
        else r--;
    }
    return best;
}
// O(n)

Module 40
Pattern: Sliding Window

When to use

  • Contiguous subarray / substring with some property.
  • "Longest", "shortest", "minimum", "with at most K".
  • Fixed-size or variable-size windows.

Two flavors

Fixed window — size k

// Max sum of any window of size k
int MaxSumK(int[] a, int k)
{
    int sum = 0;
    for (int i = 0; i < k; i++) sum += a[i];
    int best = sum;
    for (int i = k; i < a.Length; i++)
    {
        sum += a[i] - a[i - k];
        best = Math.Max(best, sum);
    }
    return best;
}

Variable window — grow until condition broken, then shrink

// Smallest subarray with sum ≥ target
int MinSubarrayLen(int target, int[] a)
{
    int left = 0, sum = 0, best = int.MaxValue;
    for (int right = 0; right < a.Length; right++)
    {
        sum += a[right];
        while (sum >= target)
        {
            best = Math.Min(best, right - left + 1);
            sum -= a[left++];
        }
    }
    return best == int.MaxValue ? 0 : best;
}
// O(n) — both pointers advance n times

Permutation in string — anagram window

bool CheckInclusion(string s1, string s2)
{
    if (s1.Length > s2.Length) return false;
    var need = new int[26];
    var have = new int[26];
    foreach (var c in s1) need[c - 'a']++;
    int k = s1.Length;

    for (int i = 0; i < s2.Length; i++)
    {
        have[s2[i] - 'a']++;
        if (i >= k) have[s2[i - k] - 'a']--;
        if (have.SequenceEqual(need)) return true;
    }
    return false;
}

Sliding window solves: longest unique substring, longest with at most K distinct, min window substring, max consecutive 1s with K flips, fruits in baskets.

Module 41
Pattern: Fast & Slow Pointers

When to use

  • Detect cycle in linked list / sequence.
  • Find middle of a list.
  • Find cycle's entry point.
  • Happy number (number-cycle detection).
  • Palindrome linked list.

Floyd's algorithm — find cycle entry

ListNode? CycleEntry(ListNode? head)
{
    var slow = head; var fast = head;
    // Phase 1: detect
    while (fast?.Next != null)
    {
        slow = slow!.Next;
        fast = fast.Next.Next;
        if (slow == fast)
        {
            // Phase 2: find entry
            slow = head;
            while (slow != fast)
            {
                slow = slow!.Next;
                fast = fast.Next;
            }
            return slow;
        }
    }
    return null;     // no cycle
}

Why does Phase 2 work? Math: distance from head to entry = distance from meeting point to entry (going around). Walk both at same speed and they meet at the entry.

Find middle (for splitting list, palindrome check, etc.)

ListNode? Middle(ListNode? head)
{
    var slow = head; var fast = head;
    while (fast?.Next != null) { slow = slow!.Next; fast = fast.Next.Next; }
    return slow;
}

Happy number — sequence cycle detection on numbers

bool IsHappy(int n)
{
    int slow = n, fast = SquareSum(n);
    while (fast != 1 && slow != fast)
    {
        slow = SquareSum(slow);
        fast = SquareSum(SquareSum(fast));
    }
    return fast == 1;

    int SquareSum(int x)
    {
        int s = 0;
        while (x > 0) { int d = x % 10; s += d * d; x /= 10; }
        return s;
    }
}

Module 42
Pattern: Top-K with Heap

When to use

  • "K largest", "K smallest", "K most frequent".
  • "K closest points to origin".
  • Online: top-K of a stream.

The trick: heap of size K, not n

For top-K largest: keep a min-heap of size K. When a new element arrives, if it's bigger than the heap's min, push and pop. After processing all n, the heap holds the top K.

// Top K most frequent
int[] TopKFrequent(int[] nums, int k)
{
    var freq = new Dictionary<int, int>();
    foreach (var x in nums)
        freq[x] = freq.GetValueOrDefault(x) + 1;

    var heap = new PriorityQueue<int, int>();   // (num, freq) — min-heap by freq
    foreach (var (num, f) in freq)
    {
        heap.Enqueue(num, f);
        if (heap.Count > k) heap.Dequeue();
    }
    var result = new int[k];
    for (int i = k - 1; i >= 0; i--) result[i] = heap.Dequeue();
    return result;
}
// O(n log k)

K closest points to origin

int[][] KClosest(int[][] points, int k)
{
    var heap = new PriorityQueue<int[], int>();   // max-heap (negate dist)
    foreach (var p in points)
    {
        int d = p[0] * p[0] + p[1] * p[1];
        heap.Enqueue(p, -d);
        if (heap.Count > k) heap.Dequeue();
    }
    var result = new int[k][];
    for (int i = 0; i < k; i++) result[i] = heap.Dequeue();
    return result;
}

Two heaps — median of a stream

public class MedianFinder
{
    private readonly PriorityQueue<int, int> _lo = new();   // max-heap (lower half)
    private readonly PriorityQueue<int, int> _hi = new();   // min-heap (upper half)

    public void Add(int n)
    {
        _lo.Enqueue(n, -n);                      // negate for max-heap
        _hi.Enqueue(_lo.Dequeue(), -_lo.Peek());
        if (_hi.Count > _lo.Count)
        {
            int top = _hi.Dequeue();
            _lo.Enqueue(top, -top);
        }
    }

    public double Median() => _lo.Count > _hi.Count
        ? _lo.Peek()
        : (_lo.Peek() + _hi.Peek()) / 2.0;
}
// Add: O(log n). Median: O(1).

Pattern: Modified Binary Search

When to use

  • Sorted array but with a twist: rotated, contains duplicates, infinite stream, 2D matrix.
  • Find peak / valley / target with property.
  • Find first/last occurrence.
  • "Binary search the answer" (Module 25).

Search in rotated sorted array

int Search(int[] a, int target)
{
    int lo = 0, hi = a.Length - 1;
    while (lo <= hi)
    {
        int mid = (lo + hi) / 2;
        if (a[mid] == target) return mid;

        if (a[lo] <= a[mid])      // left half is sorted
        {
            if (a[lo] <= target && target < a[mid]) hi = mid - 1;
            else lo = mid + 1;
        }
        else                       // right half is sorted
        {
            if (a[mid] < target && target <= a[hi]) lo = mid + 1;
            else hi = mid - 1;
        }
    }
    return -1;
}
// O(log n)

Find peak element

int FindPeak(int[] a)
{
    int lo = 0, hi = a.Length - 1;
    while (lo < hi)
    {
        int mid = (lo + hi) / 2;
        if (a[mid] > a[mid + 1]) hi = mid;       // peak is to the left or here
        else lo = mid + 1;                        // peak is to the right
    }
    return lo;
}

Find first/last occurrence

int FirstOccurrence(int[] a, int target)
{
    int lo = 0, hi = a.Length - 1, ans = -1;
    while (lo <= hi)
    {
        int mid = (lo + hi) / 2;
        if (a[mid] == target) { ans = mid; hi = mid - 1; }
        else if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return ans;
}
// Switch hi=mid-1 with lo=mid+1 in the equal case for last occurrence.

Pattern: BFS/DFS on Matrices

When to use

  • Grid problems: islands, regions, paths, walls.
  • Multi-source BFS: nearest hospital/police, rotting oranges.
  • Flood fill, paint bucket.
  • Shortest path in maze.

The pattern

int[][] dirs = { new[] { 0, 1 }, new[] { 0, -1 },
                 new[] { 1, 0 }, new[] { -1, 0 } };

void BfsGrid(int[][] grid, int sr, int sc)
{
    int rows = grid.Length, cols = grid[0].Length;
    var visited = new bool[rows, cols];
    var q = new Queue<(int r, int c)>();
    q.Enqueue((sr, sc));
    visited[sr, sc] = true;

    while (q.Count > 0)
    {
        var (r, c) = q.Dequeue();
        Visit(r, c);
        foreach (var d in dirs)
        {
            int nr = r + d[0], nc = c + d[1];
            if (nr < 0 || nc < 0 || nr >= rows || nc >= cols) continue;
            if (visited[nr, nc] || /* obstacle */ grid[nr][nc] == 0) continue;
            visited[nr, nc] = true;
            q.Enqueue((nr, nc));
        }
    }
}

Rotting oranges — multi-source BFS

Problem

Grid: 0=empty, 1=fresh, 2=rotten. Each minute, rotten infects orthogonal neighbors. Min minutes until all rotten? Or -1 if impossible.

int OrangesRotting(int[][] grid)
{
    int rows = grid.Length, cols = grid[0].Length;
    var q = new Queue<(int r, int c)>();
    int fresh = 0;

    for (int r = 0; r < rows; r++)
        for (int c = 0; c < cols; c++)
        {
            if (grid[r][c] == 2) q.Enqueue((r, c));
            else if (grid[r][c] == 1) fresh++;
        }

    int[][] dirs = { new[]{0,1}, new[]{0,-1}, new[]{1,0}, new[]{-1,0} };
    int minutes = 0;

    while (q.Count > 0 && fresh > 0)
    {
        int size = q.Count;
        for (int i = 0; i < size; i++)
        {
            var (r, c) = q.Dequeue();
            foreach (var d in dirs)
            {
                int nr = r + d[0], nc = c + d[1];
                if (nr < 0 || nc < 0 || nr >= rows || nc >= cols) continue;
                if (grid[nr][nc] != 1) continue;
                grid[nr][nc] = 2;
                fresh--;
                q.Enqueue((nr, nc));
            }
        }
        minutes++;
    }
    return fresh == 0 ? minutes : -1;
}
// O(R·C)

  • Gives you a reference to compare optimized solutions.
  • If you're stuck, brute force is fine — partial credit beats no code.

Then optimize: "now let me see if I can do better."

How to Practice

The wrong way

  • Grinding hundreds of random problems with no structure.
  • Reading solutions before trying.
  • Solving once and never revisiting.
  • Skipping problems you got wrong.

The right way

Phase 1: Foundations (4–6 weeks)

  • Master Modules 1–13 of this course (foundations + linear structures).
  • Solve 30 easy problems across arrays, strings, linked lists, hash tables. Aim for 1 per day.
  • For each: brute force first, then optimized. Write both.
  • State complexity out loud.

Phase 2: Patterns (6–8 weeks)

  • Master Modules 14–37 (trees/graphs/sorting/DP/backtracking).
  • For each pattern (Modules 38–44), solve 5–10 medium problems.
  • Use NeetCode 150 or Blind 75 lists as a curated set.
  • Time yourself: 30 min per medium, 45 min per hard.
  • If you can't solve in time, look at the approach (not the code), then close the page and try again.

Phase 3: Polish (2–4 weeks)

  • Mock interviews — Pramp, Interviewing.io, or with peers.
  • Re-solve your hardest problems without notes.
  • Practice explaining solutions out loud while coding.
  • Solve company-tagged questions for your target companies.

Daily ritual (45 min)

  1. 5 min — review yesterday's problem mentally.
  2. 30 min — solve one new problem (UMPIRE).
  3. 10 min — read the optimal solution; note what you missed.

Spaced repetition

Tag every problem you solved as "easy/medium/hard" and "got it / struggled / failed". Re-solve the "struggled / failed" ones after 1 day, 1 week, 1 month. Anki-style.

Keep a journal

For each non-trivial problem, write down:

  • Problem in one line.
  • Pattern recognized.
  • Brute force complexity.
  • Optimized approach + complexity.
  • What tripped you up.

Re-read the journal weekly. You'll start seeing your blind spots cluster.

Module 50
Mock Interview Tips

Before the interview

  • Sleep enough. Tired solving = bad solving.
  • Test your dev environment if it's a coding round.
  • Have water nearby.
  • 5-minute warm-up: do an easy problem you know cold.

During the interview

Talk continuously

Silence is the enemy. Even if you're stuck, narrate: "I'm thinking this might be a sliding window problem because... but I'm not sure how to handle this case..." The interviewer will hint or steer.

Pace

For a 45-minute interview:

  • Minutes 0–5: clarify the problem.
  • Minutes 5–10: discuss approaches; pick one.
  • Minutes 10–30: code.
  • Minutes 30–40: trace, fix bugs.
  • Minutes 40–45: complexity, edge cases, follow-ups.

If stuck

  1. Re-read the problem.
  2. Try a smaller example.
  3. State the brute force.
  4. Ask: "what kind of problem feels like this?"
  5. Ask the interviewer: "I'm considering X but not sure — does it sound right?"

If you finish early

Discuss:

  • "Is there a way to reduce space?"
  • "What if the input were streaming?"
  • "How would I scale this to 10⁹ items?"
  • "What if duplicates were allowed?"

Common scoring criteria

  • Communication — did you explain your thinking?
  • Problem-solving — did you make progress on your own?
  • Coding — clean, idiomatic, working code?
  • Verification — did you test / trace / find bugs?
  • Complexity — could you analyze it?

You don't need a perfect solution to do well — strong communication often beats a perfect-but-silent answer.

Where DSA can improve specific EasyAudit features

1. Master-data cascading deletes

DeleteValidationService + CatalogReferenceChecker in central-backend check whether a master record is used. The check is naturally a graph problem — entity → tables that reference it → tables that reference those.

  • Build the reference dependency graph once at startup.
  • BFS from the candidate-for-deletion to surface every blocking reference.
  • Topological sort if the user wants to delete a whole subtree in one go.

2. User-rights tree

Permissions in EasyAudit follow a hierarchy: Module → MenuItem → Action. Storing as a tree (parent + children) and computing "effective rights" with DFS is the natural model.

  • Cache the precomputed flattened set per (user, organization, year) in Redis.
  • Invalidate on role change.
  • Lookup is O(1) for "can user do X" via a HashSet.

3. Multi-tenant org/year switching

useUserOrganizations + useYearsByOrganization on the frontend produce nested combos. If org count grows large, compute the (org → years) map once and serve it from a sorted structure for fast lookup. Trie-of-strings is overkill; a Dictionary<orgId, List<Year>> ordered by year suffices.

4. Document folder hierarchy

FolderService, DocumentService manage a tree. Common operations:

  • "All documents under this folder" — DFS.
  • "Path from root to current folder" — climb parent pointers.
  • "Move a folder" — detach + attach (cycle check via DFS).
  • "Rename schedule" — appears to be a tree-of-renames; ordered application is a topological sort.

5. Notification fan-out

When a system event happens, fanning out to all tenants/users is a graph traversal. Add per-user idempotency key (HashSet in Redis) to prevent duplicates.

6. Report generation (accounting backend)

BalanceSheetService, ProfitAndLossService, TrialBalanceService, LedgerReportService traverse the chart of accounts. Account hierarchy = tree.

  • Compute leaf totals once.
  • Roll up to parents via post-order traversal.
  • Cache the rolled-up tree in Redis for the duration of a year (invalidate on JV post).

7. Excel import duplicate detection

Importing journal vouchers, items, parties — checking for duplicates against existing rows. HashSet of natural keys → O(n) instead of N×M lookups against the DB.

8. Search-as-you-type

page-search, settings-search, master-data autocomplete. A trie of indexed strings + top-K heap of matches gives sub-millisecond response. For now you likely use string-Contains on a small list — when the data grows, swap in a trie.

9. Recent-activity ring buffer

ActivityLogService writes events. For "show last 100 actions per user", use a Redis List with LTRIM — O(1) per write, O(100) per read.

10. Rate limiting OTP requests

"User can request OTP at most N times per hour" = sliding window over a Sorted Set in Redis (Redis course Module 32).

The DSA mindset for production code

Before writing a loop, ask:

  • What's the input size today? In 1 year? In 5?
  • What's my current complexity? Is it safe at projected size?
  • Is the data already in a structure that makes this fast?
  • Could a Dictionary turn this O(n²) into O(n)?
  • Could an index in SQL turn this O(n) full-scan into O(log n) seek?

You don't need clever code. You need code that won't suddenly become slow when usage doubles.
